# Diario de desarrollo — 2026-10-12

## Icono incrustado para el menú nativo de añadir a inicio

- Las capturas del iPhone posteriores al despliegue confirman que Safari muestra el logo al compartir, pero el menú «Añadir a pantalla de inicio», con «Abrir como app web» activado, sigue mostrando la inicial R. Las comprobaciones HTTP de la corrección anterior no verificaban ese menú y no resolvieron el caso.
- `app/index.html` incluye ahora el PNG aprobado de 180 × 180 íntegro en el enlace `apple-touch-icon`, como URL de datos. El menú recibe la imagen con el documento y no necesita otra descarga del icono. Se mantienen las rutas de respaldo y el manifiesto. No se cambia el arte, la política de seguridad ni el modo de apertura.
- Safari admite URL de datos para iconos desde la versión 26, según [WebKit](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/). Es una corrección para evitar la dependencia de una descarga adicional; no se ha confirmado la causa interna del fallo de Safari.
- Añadido `node scripts/embed-app-icon.mjs` para sincronizar el PNG y el HTML cuando cambie el arte. La prueba HTTP exige una URL de datos y compara el PNG incrustado con el servido byte a byte.
- Verificación con Node 24.21.0: 4/4 pruebas específicas pasan y el verificador del logo aprobado pasa. Chrome aislado con ancho móvil y CSP real decodifica el PNG de 180 × 180 sin conexión, con cero peticiones de icono y cero errores CSP. No hay runtimes de iPhone instalados para verificar el menú nativo en un simulador; sigue pendiente de comprobar en el dispositivo del usuario. Sin llamadas a OpenAI.
- Se conserva la autorización del usuario para publicar esta corrección en `main`. El despliegue se comprueba después del push.

## Compatibilidad del icono al guardar en inicio desde Safari

- Comprobada producción: `/app/` ya enlaza el icono anterior, `/apple-touch-icon.png` devuelve HTTP 200 y su PNG RGB opaco de 180 × 180 coincide byte a byte con el del repositorio. No se confirma la causa específica en el iPhone; no es simplemente un icono ausente del despliegue.
- El HTML usa ahora `/apple-touch-icon-v2.png`, una dirección nueva para solicitar la imagen sin reutilizar la URL anterior. Se conservan las rutas convencionales, incluidas las variantes `-precomposed` y `-180x180`, tanto en la raíz como en `/app/`.
- Añadido `app/manifest.webmanifest`, servido como `application/manifest+json`, con nombre Reedleaves, inicio en `/app/#home` e iconos PNG opacos de 192 y 512 px. Rasterizados desde el SVG aprobado con el mismo encuadre del icono de 180 px. Se conserva `display: browser`; no se añade funcionamiento sin conexión ni se cambia la sesión.
- Verificación: 4/4 pruebas específicas HTTP y de nombre pasan con Node 24.21.0; el verificador del logo aprobado también pasa. La prueba nueva comprueba descubrimiento desde una URL con consulta y fragmento, manifiesto, dimensiones, PNG RGB, GET/HEAD y ausencia de sesión, acceso SQL y redirecciones. Revisados visualmente los PNG de 180 y 512 px.
- La batería completa conserva ocho fallos previos de álbum, perfiles y privacidad de borradores. Reproducidos los mismos ocho en una copia temporal del código sin esta corrección: 177/185 pasan. Sin llamadas reales a OpenAI.
- Publicación a `main` autorizada por el usuario. El despliegue se comprueba después del push; el menú «Añadir a pantalla de inicio» requiere confirmación en un iPhone real.
